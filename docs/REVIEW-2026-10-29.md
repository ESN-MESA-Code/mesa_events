# Review 2026-10-29 – flaws to fix

Second review after the 2026-10-28 round (commits 8eaf750…78c0130): the new migrations and
changed code, plus a hands-on walkthrough on the local stack (OC, Volunteer, Events, Comms, phone
width). The previous round's items are done; these are new findings. Everything here is in scope;
work through it in order A → B.

## A. Flaws in behaviour

**A1. "Run it anyway" does not stick.** When the OC decides an under-staffed event runs,
`decideUnderstaffed` sets it to `confirmed`. The next roster change (someone claims one of the
still-open slots, a helper drops out) calls `private.refresh_staffing()`, which sets it back to
`understaffed` while helpers are still short – and the OC is asked again.
- Store the decision (e.g. `events.understaffed_decision` = `run` with who/when, set only by the
  decision) and let `refresh_staffing()` keep `confirmed` while it is set. Clear it when the event
  loses its OC (the new OC decides again).
- DB tests: decide run → a helper claims (still short) → stays confirmed; OC drops out → back to
  under-staffed with the decision cleared.

**A2. Cancelling an event tells nobody and cannot be undone.** `cancel` only flips the status.
The helpers, the Chat space, Comms (the description may already be published) and the Events team
learn nothing, and the status is final.
- On cancel: enqueue a Chat message to the event's space (OC and helpers mentioned) via the jobs
  queue (idempotent key), and show the cancellation on the Comms dashboard if the description was
  published (Comms decides whether to post a correction).
- The Events team can reopen a cancelled event (back to the staffing-derived status), logged.
- The confirm dialog states the consequences ("The team and the Chat space are told; registered
  receipts stay valid").
- Tests: DB (job enqueued once, reopen only by Events), E2E for the cancel flow.

**A3. Events never become "completed".** Nothing sets `status = 'completed'`, so past events show
"Confirmed" or "Under-staffed" forever (My events → Past events, Events dashboard), and an event
that started today is listed under "Coming up" (Language Café at 00:13).
- Add a pg_cron job (via the jobs pattern or a plain SQL function on a schedule, using
  `mesa.system_update`) that marks `confirmed`/`understaffed` events `completed` once they ended
  (`coalesce(ends_at, starts_at + interval '1 day')` in the past).
- Grep every status filter (attendance, hand-in, receipts, photos, description overview,
  checklists, labels) so `completed` events keep working where `confirmed` ones do.
- My events: "Today" / "Coming up" / "Past" by start and end time, past ones labelled by hand-in
  state ("Hand-in open", "Done").
- DB test for the job; unit tests for the grouping.

**A4. Cycles never finish.** The October 2026 cycle (all events past) still shows "Descriptions:
Remind OCs whose descriptions are missing" on the Events dashboard and the Home queue.
- Extend the cycle stepper with the post-event phase: … → Descriptions → **Hand-in** (attendance
  lists signed off, photos, Belege: "3 of 5 events handed in") → **Done**.
- The Descriptions step stops asking for reminders once the cycle's events have happened.
- Done cycles move to a collapsed "Past cycles" list on the Events dashboard and drop out of the
  Home queue and the Comms per-month progress.

**A5. Deadlines are not checked against the month.** The description deadline (one for all events)
and the volunteer form deadline can be set after the cycle's events start; the demo seed does it
(October events, description deadline 31 Oct).
- Database: refuse a description deadline after the start of the cycle's first event, and a form
  deadline after the first day of the cycle's month (Europe/Berlin). Keep the error messages plain.
- UI: say the latest allowed date next to the inputs.
- Fix the seed so every demo cycle's deadlines are before its events.
- DB tests for both checks.

**A6. Comms "Late" mixes chasing and history.** An event that already happened without a
description sits under "Late" forever (Pub Crawl, 22 Oct).
- Split: **Late** = deadline passed and the event is still ahead (chase the OC); **Missed** = the
  event happened without a published description (collapsed, informational).
- The Home Comms queue counts only Late.

**A7. Test runs leave junk in the dev database.** The DB and E2E suites use the same local
database as `npm run dev:local` and leave cycles in 2047–2081 with "Hike xxxxx" / "Quiz xxxxx"
events behind. The monthly-cycle E2E also moves events with the service role to dates outside their
cycle's month, bypassing the new cycle-month guard, so the dev UI shows cycles whose events are in
October 2026.
- Every suite removes what it created (a global teardown deleting by the test tag; mind the
  foreign keys: claims, receipts, assignments, events, cycles, ideas, jobs, fake tables).
- Tests that move event dates keep them inside the cycle's month (or use a cycle for the current
  month), so the data never breaks an invariant the app relies on.
- After `npm run test:db` and `npm run test:e2e`, the Events dashboard shows only the demo data.
  Clean the current local database once (`seed:demo` after removing the leftovers).

## B. Wording and small UI issues

**B1.** On an unpaid claim, My events shows "Paid to PayPal olga@example.com". Use "Payout: PayPal
(olga@…)" until it is paid, "Paid to …" afterwards.

**B2.** Hand-in status counts every receipt of the event ("Receipts registered: 3 · 1 Beleg(e)
not handed in yet") while "Your receipts" lists only your own two, so the OC cannot see which Beleg
is missing. Show yours and the team's separately ("Yours: 2, all Belege in · Rest of the team:
1 Beleg outstanding") without other people's amounts.

**B3.** Plurals: "1 helper slot(s) are open", "1 helper(s) missing", "Beleg(e)". Use one plural
helper everywhere (grep for `(s)` and `(e)` in the UI).

**B4.** The "Your next step" banner links to the tab you are already on ("Overview →" on the
Overview). On the same tab, scroll to the action (anchor) instead of linking to itself.

**B5.** A claim card shows "Beleg received" twice (the step row and a status badge). Drop the
badge where the steps are shown.

**B6.** The under-staffed banner says "As OC you decide" to everyone who sees it, also the Events
team and when the OC dropped out. Word it per viewer; without an OC, say the Events team decides.
