# Review 2026-10-28 – changes to implement

Code review and a hands-on UI walkthrough (local stack, roles Member, OC, Events, Executive)
of the Phase 1 build. Part A are new product decisions from the user, part B the code review,
part C the UI/flow review. Everything here is in scope; work through it in order A → B → C.

## A. Product changes (decided by the user)

**A1. The volunteer form locks after submitting.** A volunteer submits once per cycle; after
that their answers are read-only.
- `submit_volunteer_form()` refuses a second submission for the same cycle and person.
- The Volunteer page shows a read-only summary after submitting ("You signed up for: …, ask the
  Events team if something changes").
- Escape hatch for mistakes: the Events team can clear one person's response on the cycle page
  (logged), after which that person can submit again. Record this in DECISIONS.md.
- FCFS ties now use the single submission time (`volunteer_responses.submitted_at`) for all of a
  person's choices; drop per-choice `chosen_at` or set it from `submitted_at`. Update
  `lib/allocation.ts`, tests and the form copy.

**A2. No digital receipt photos.** The paper Beleg is mandatory, so storing a photo adds
nothing. Receipts stay registered as data (kind, amount, vendor, date, note) for tracking.
- New migration: drop `receipts.reference_path`, the `receipts` Storage bucket and its
  policies, and the reference-photo check in `register_receipt()` (keep the function's other
  behaviour; adjust its signature).
- Remove the upload field from the hand-in form, the `/api/receipts/[id]/file` route, the photo
  column/indicator in the Finance claims table, related tests, docs and privacy text.
- Event photos (hand-in photos → Drive) stay as they are.

## B. Code review findings

**B1 (must fix) – activity log leaks reimbursement claims to event staff.** The
`log_reimbursements` trigger writes full claim rows into `activity_log` with the claim's
`event_id`, and the `activity_log` select policy lets any OC/helper of that event read them
(claimant, amounts, flags, payout method, finance note, rejection reason). Fix so claim log
entries are visible only to Finance (and executives/admins if wanted), e.g. log them without
`event_id` or with an entity-based policy. Add an RLS test with a **real** claim as a helper of
the same event. Check the other logged tables for the same pattern.

**B2 – dropout reasons visible to all members.** `assignments.drop_reason` is shown on the
event page to everyone who can read the roster. Show it only to the OC and Events team (column
not exposed to others, e.g. a view or definer function), and add a hint not to enter health
details.

**B3 – OC can move their event's date.** `guard_event_update()` lets the OC change
`starts_at`/`ends_at` (and location, price, capacity). Dates must be Events-only (they drive the
month schedule, volunteer choices and which reimbursement policy applies). Decide and document
whether location/price/capacity stay OC-editable.

**B4 – stale running jobs bypass `max_attempts`.** `claim_jobs()` re-claims jobs locked > 10
minutes without checking attempts, so a job that hangs or crashes the runner loops forever.
Mark such jobs `dead` once `attempts >= max_attempts`. Add a DB test.

**B5 – every server action revalidates the whole app.** The generated wrappers call
`revalidatePath("/", "layout")` after every action, including description autosave every few
seconds. Skip revalidation for autosave and revalidate only affected paths elsewhere (let
`defineAction` declare what to revalidate).

**B6 – CI.** Add `.github/workflows` (lint, typecheck, unit, db against a local Supabase, e2e,
bundle scan, docker build) – files only, nothing pushed. Add an `npm run gen:actions` script and a
check that the generated `app/actions/*` match `lib/actions/*`.

**B7 – `npm run seed:demo` fails on re-run** (`delete cycles: … violates foreign key
constraint events_cycle_id_fkey`) when the demo cycles contain events not prefixed `[demo]`.
Make the cleanup robust.

(Legal texts still need updating by the board – out of scope, keep the note in PROGRESS.md.)

## C. UI and flow review

Overall the pages work, but the app is organised by data (calendar, ideas, volunteer, teams)
instead of by "what do I need to do now". Members and OCs have to know where to look.

**C1. A home page that answers "what's next for me".** Make `/` (and the logo link) a
role-aware Home:
- Open volunteer form banner with deadline (or "submitted ✓" summary).
- My upcoming events, each with its next action and deadline ("Write description – due Sat 31
  Oct", "Hand in photos and Belege", "Decide: run under-staffed?").
- Open slots I could claim.
- My claims needing something (payout details missing, Beleg not handed in).
- For team members: a compact card per team queue (Events: cycle step + unstaffed events;
  Comms: awaiting review / late; Finance: Belege to receive, claims to check, batch to pay) linking
  to the team page.

**C2. Cycles are labelled by the wrong month.** The cycle "November 2026" holds December
events, and "October 2026" holds November events, while ideas are matched to cycles by their own
date. Nothing checks that an event's date falls in its cycle's month (the demo seed puts them in
the next month). Make the cycle month = the month of its events everywhere, label it e.g.
"December 2026 events" (with "planned in November" as secondary info), validate event dates
against the cycle month in the database, fix the seed, and use the same label on the Volunteer
page and dashboards.

**C3. Navigation structure.** Today one flat bar mixes personal and team pages (7 items for an
executive) and "Volunteer" is always there even when no form is open.
- Personal: Home, Calendar, My events, Ideas. Volunteer appears as a Home banner and a nav item
  with a badge only while a form is open (or the page explains when the next one opens).
- Teams: a separate group (second row, or a "Team" menu) with Events, Comms, Finance, Admin.
- Mobile: check the nav at phone width (horizontal scroll vs. menu).

**C4. Executive sees "Finance" in the nav but gets a 404.** `lib/nav.ts` shows Finance to
executives, the page requires the finance role. Either give executives read-only Finance
(preferred, matches "executives see everything") or hide the link. Also the 404 page renders
unstyled on a black background inside the app – add a styled `not-found` with a way back (and a
proper "no access" page instead of 404 where the user is signed in but lacks the role).

**C5. Event page: checklist → actions.** Make every checklist item a link to the right tab with
its deadline and a primary next-step banner at the top for the OC. Breadcrumbs that reflect where
the user came from (My events / Calendar / team page) instead of always "← Calendar". Hide the
technical "Recent activity" (`events update`, `assignments insert`) from staff or rewrite it in
plain language; keep the raw log for Events/admins.

**C6. Event tabs follow the event's phase.** Before the event, Hand-in shows the receipt form
although "the event has not started yet". Order each tab's content as status first, then
actions; show what is not yet relevant as disabled with a short reason (e.g. "Hand-in opens
after the event").

**C7. My events – claims.** A claim with status "Beleg received" reads "Paid € 31.50 ·
suggested € 31.50", which looks contradictory. Label amounts clearly (Receipt amount /
Suggested / Approved / Paid) and show each claim's progress as steps (Registered → Beleg received →
Checked → Paid). Group claims by event.

**C8. Comms dashboard.** Events that already happened without a description sit under "Due"
(because the deadline is monthly) instead of "Late". Count an event as late when its deadline has
passed or it has started; show progress per cycle (e.g. "5 of 8 descriptions in").

**C9. Events team: a step-by-step cycle page.** The cycle page and the team dashboard are long
mixed lists. Show each cycle as a stepper – Ideas → Schedule → Volunteer form → Allocation →
Roster confirmed → Descriptions – with the current step's main action highlighted, and the
dashboard as one card per cycle with its step.

**C10. Description editor shows "Unsaved changes" right after loading** with nothing edited.
Find and fix the cause.

**C11. Consistency pass.** Same status chips, date formats, empty states and button styles on
every page; check every page at 375 px width (OCs use phones on event day).
